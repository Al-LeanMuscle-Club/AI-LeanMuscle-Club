# 成员使用指南

[English](MEMBER_GUIDE.md) | **简体中文**

可以先随手记一次运动、一顿饭，或者参与交流。周计划可选；需要计划打卡和复盘时，每人每周用一个 Issue。无需每天提 PR，也不要求身材照片、详细运动数据或参加排行榜。

以下示例均为假想模板，不代表真实成员的活动，也不是规定训练计划。请按自己的情况选择运动、节奏和记录详略。

## 选择适合自己的参与方式

- [自由运动记录](https://github.com/Al-LeanMuscle-Club/AI-LeanMuscle-Club/issues/new?template=activity-record.yml)：不需要周计划或命令，写下今天做了什么；此类 Issue 不参加排名。
- [饮食记录](https://github.com/Al-LeanMuscle-Club/AI-LeanMuscle-Club/issues/new?template=meal-record.yml)：不要求周计划、热量或照片；独立 Issue 不参加排名，也不自动进入周计划饮食天数汇总。
- [社区 Issues](https://github.com/Al-LeanMuscle-Club/AI-LeanMuscle-Club/issues/new/choose)：新人报到、提问、分享、找搭子和活动公告，选择对应话题表单即可。
- **Weekly training plan**：如果想按计划记录，并可选参加每周参与积分榜，使用下面的周计划流程。

[六类虚构示例](../examples/README.md)可以参考格式。无论选择哪种方式，原 Issue 和讨论都是公开的。

## 1. 按本周科研安排制定计划

打开 **Weekly training plan** Issue 表单，填写该周周一的日期、IANA 时区、参与模式和排行榜选项。还可以选填 **Primary goal** 和 **Research week**，方便找到背景相近的计划。

| 字段 | 选项 | 含义 |
| --- | --- | --- |
| Primary goal | `fat-loss` 减脂、`muscle-gain` 增肌、`cardio` 心肺、`skill` 技术、`habit` 维持习惯 | 当前阶段的主要目标，可以在之后的周计划中调整 |
| Research week | `regular` 常规、`deadline` 赶稿、`travel` 出差 | 帮助理解时间安排，不改变积分倍率 |
| Participation mode | `Active`、`Recovery` | Recovery 周退出计分排名 |
| Public leaderboard | `No`、`Yes` | 是否同意生成的报告展示用户名及允许公开汇总的字段 |

未填写的可选分类默认按 `habit` 和 `regular` 处理。目标与运动项目独立：以增肌为主，也可以在同一周安排力量训练和篮球。

在 **Planned sessions** 中，每次训练写一行：

```text
S1 | Tuesday | strength | 自己选择的短训练 | 在家完成的替代方案
S2 | Thursday | basketball | 和朋友练球
S3 | Saturday | running | 自己选择的路线
```

各列依次是 `编号 | 星期 | 运动项目 | 内容`，可在第五列为这次训练预先写一个忙周替代方案。星期使用完整英文 `Monday` 至 `Sunday`；编号从 `S1` 至 `S99` 中选择，保持稳定且互不重复。Active 计划包含 1–14 次训练，休息日写在 Notes。

运动项目使用 `strength`、`basketball`、`running`、`swimming`、`cycling`、`walking`、`mobility`、`other`。每次训练选一个主要项目，混合内容写在说明中；同一周的不同训练可以属于不同项目。

旧版三列格式 `S1 | Tuesday | 训练内容` 仍可用，项目归为 `other`。希望按项目筛选时，请使用四列格式。内容或替代方案内部不要再加 `|`，它用于分隔各列。

请提前写好这次训练的替代方案。通用 **Busy-week fallback** 字段可记录整体思路，但 `/fallback` 计为完成需要对应训练在第五列有明确方案。调整时保留原承诺及说明，避免为了提高分数而改写过去的计划。

第一次成功同步报告会确认本周计分活动的快照。之后可以调整当前安排，但删除未完成活动不会缩小已确认的计分分母；新增活动可以记录，却不额外增加本周执行积分。报告会区分当前计划与已确认计划。修改时请说明原因，并保留已完成活动的编号。确认时点与更正规则见[评分说明](SCORING.md)。

## 2. 用简短评论记录训练

在自己的周计划 Issue 下，评论的首个非空行放一个命令。日期使用该次训练在所填时区中的实际日期。可以补记该周周一至周日内的过去日期，未来日期不计入。

| 命令 | 含义 | 执行积分 |
| --- | --- | --- |
| `/done S1 2026-10-27` | 完成原计划 | 计为完成 |
| `/fallback S1 2026-10-27` | 完成 S1 第五列中预先声明的方案 | 计为完成，S1 最多一次 |
| `/partial S1 2026-10-27` | 完成了一部分 | 半次执行额度，不算完整完成 |
| `/skip S1 2026-10-27` | 没有进行这次训练 | 保留状态，不计完成积分 |

选填感受可以放在 `|` 后，或写在后续行：

```text
/done S2 2026-10-29 | 和朋友练了一会篮球。
今天重点：自己想练的技术。
训练后精力：感觉放松了一些。
```

同一编号以最新有效记录为准，状态不会累加。记错时可以补一条新的有效状态，也可以编辑或删除错误评论。完成原计划和完成替代方案不会让同一个 S1 获得两次完成积分。

只有本人在本人计划下的记录计分。不同命令请分开评论；同一条评论里出现第二个命令行，会因歧义而不计入。普通交流和选填说明都欢迎。没有打卡只代表 **尚未记录**，不能据此判断一个人没有运动。

### 不同项目的选填详情

| 项目 | 可以记录的细节 |
| --- | --- |
| 力量训练 | 动作、组数、次数、重量、临时调整 |
| 篮球 | 技术练习或比赛、练习重点、时长、体会 |
| 跑步 | 时间、距离、配速、主观强度 |
| 游泳或骑行 | 时间、距离、体会 |
| 步行或活动度练习 | 时间、具体内容、怎样安排进当天的日程 |

这些都是服务个人回顾的可选信息，不是打卡门槛或排名标准。自由文字和身体指标不会复制到生成的报告数据中；如果主动写入原 Issue，它们在原帖中仍是公开内容。

## 3. 饮食记录按需使用

可以在同一个周计划 Issue 下发布饮食评论：

```text
/meal 2026-10-28 | 午餐
食物和分量：自己的描述，可选照片。
估算来源：包装标识／称重配方／本人估算／模型估算。
估算热量范围：选填，不清楚时留空。
假设或未知信息：分量、烹调用油、酱料或其他缺失背景。
想观察的事情：这周科研安排下，怎样更方便地安排饮食。
```

按自己的时区填写该计划周内的日期。不要求热量、照片或完整配方。填写数值时，请同时保留来源和不确定性，有新信息可以修正；模型估算不等于测量结果。

报告可展示周计划内有效 `/meal` 的不同日期天数：同一天两餐仍只算 1 个饮食记录日。这是记录天数，不是餐食评级；独立饮食 Issue 不进入该汇总。

仓库没有运行自动热量估算器或餐食健康评分服务。饮食记录不额外加分，吃得更少或发更多照片都不会提高分数。饮食反思可以写进正常周复盘，也可以整理为经验分享，继续遵循现有每周上限。原始饮食文字、照片和热量数字不会导出到生成的公开索引或报告 JSON。

## 4. 周末做一次复盘

发布以 `/review` 开头、后面有几句话的评论：

```text
/review
这周有效的安排：在开始实验前给一次运动留出了时间。
遇到的障碍：deadline 改变了晚上的安排。
下周调整：保留现实可行的替代方案，并调整一个时间段。
可选 Agent 记录：分担了什么任务，检查和返工花了多久，
实际净省下多少时间，是否真的用来运动或休息。
```

没有按计划完成的一周，也可以获得同样的 2 分复盘积分。科研产出、引用量、身体指标和健康结果不参与评分。

每周仍最多 **10 分**：计划 1 分、执行 0–6 分、复盘 2 分、审核通过的经验贡献 0–1 分。执行额度按完整或替代完成为 1、partial 为 0.5，除以已确认计分活动数。完整完成率仍只统计完整或替代完成。积分描述参与，不代表健身实力。细节见[完整评分规则（英文）](SCORING.md)和[虚构排名示例](../examples/ranking.md)。

经验分享的 **Week starting** 可以留空；只有申请每周贡献认可时才填写归属周一。普通分享不需要为积分选择周次。

社区 Issue 发帖和回复不会自动加贡献分。经验 Issue 必须同时具备 `points-approved` 标签和匹配当前正文、作者、周次的可信仓库审批记录；单独标签不足以计分，修改已审批正文后需重新审核。维护者通过[设置指南](SETUP.md)中的流程生成待审查审批记录。

需要退出计分时，选择 `Recovery`，或评论 `/pause`。暂停会持续到你编辑或删除该评论为止，重复发送 `/pause` 不会切回计分状态。

## 浏览器辅助页

[成员辅助页](../tools/index.html) 可以准备搜索链接、打卡文字和可复用的计划草稿，不要求凭据，也不会替你发帖。在 GitHub 文件浏览器中看到的是 HTML 源码，页面不会运行。下载仓库后，在本地打开 `tools/index.html`。如果浏览器限制本地文件读取数据，可以在仓库根目录运行：

```bash
python3 -m http.server 8000
```

之后打开[本地辅助页](http://localhost:8000/tools/)。维护者配置 Pages 并启用部署工作流后才会有托管版本，见[设置指南](SETUP.md)。请检查生成的内容，再自行粘贴到 GitHub。

在辅助页的“今天做了什么”填写一句真实记录即可准备自由运动草稿。日期与时区按当前设备填写，可以修改后补记；旅行时请核对活动发生地的时区。运动名称显示中文，生成内容保留原表单使用的运动分类。点击“到 GitHub 检查并发布”打开已预填日期、时区和文字的表单，按照提示选择运动项目，核对后自行提交；也可展开复制完整草稿。草稿不会自动发布，更多文字与照片可在 GitHub 补充。

“看看大家”和各话题入口打开真实 Issue 搜索，包括尚未补标签的帖子，排除标记为示例或标题注明虚构的演示。示例另外保留为写作参考。

报告包含社区近况时，辅助页会展示所选周发帖或回复人数、新帖子和人工回复数，按 UTC 发布时间统计，不按运动发生日期统计。人数包含自由记录、经验分享、其他交流与周计划的发帖者和回复者；示例、机器人和开发任务不计入。这些是社区参与统计，不加积分，不改变具名周榜的公开选择。旧报告没有此统计时不会补成 0。

在“我的公开记录”输入完整 GitHub 用户名，可以查看已加载的公开周计划汇总。下方“回顾我的自由记录”会按所选仓库、作者和 `activity-record`／`meal-record` 标签生成搜索链接，包含打开和已关闭的 Issue。没有周计划或已发布周报也可以使用。点击后到 GitHub 查看；自由记录不加分，也不并入周计划的天数统计，辅助页不会下载这些记录或要求 token。

所选周报和每条个人历史记录会显示报告标注的评分规则版本。**v2** 使用 partial 半次执行额度、已确认计划分母和绑定正文的贡献审批。历史报告没有版本时，页面显示“规则版本未记录”并保留原分数，不猜测旧版本，也不套用当前公式重算。尚无对应公式说明的版本会保留其原版本号与原分数。网页展示最近一次发布的快照；手动发布及报告更新后可选的自动发布方式见[设置指南](SETUP.md)。

## 命令行工具

也可以在仓库根目录使用命令行工具。全局参数写在 `find`、`carry`、`check` **之前**。在线读取所需的凭据见[设置指南（英文）](SETUP.md)；不要把 token 写进 Issue 或浏览器辅助页。

查找某周计划：

```bash
python scripts/member_tools.py --repository Al-LeanMuscle-Club/AI-LeanMuscle-Club find --handle YOUR-HANDLE --week 2026-10-26
```

从已有 Issue 生成下一周草稿：

```bash
python scripts/member_tools.py --repository Al-LeanMuscle-Club/AI-LeanMuscle-Club carry --issue 123 --week 2026-11-02 --output next-week.md
```

这只会生成草稿，排行榜同意选项会重置为 **No**。请检查新周日期、目标、日程、替代方案和公开选项，再创建新 Issue；该周已有计划时不要重复创建。

发布前检查计划或评论格式：

```bash
python scripts/member_tools.py --repository Al-LeanMuscle-Club/AI-LeanMuscle-Club check --issue 123
python scripts/member_tools.py --repository Al-LeanMuscle-Club/AI-LeanMuscle-Club check --issue 123 --comment-file check-in.txt
```

离线时，可以在子命令之前添加全局参数 `--fixture /path/to/synthetic-issues.json`。假想数据只用于测试，不能作为真实社区活动生成报告。

## 公开分享范围

公开仓库中的 Issue、评论和照片都是公开内容，即使排行榜选了 **No** 也一样。生成的索引和报告行只包含主动同意的 Active 成员，这不会改变原帖的可见性。公开汇总行可以包含目标与科研周类型、运动项目、训练状态及日期、完成次数、执行额度、当前与已确认计划摘要、饮食记录天数和积分；不会包含自由文字、热量数字或个人备注。

身材照片、具体体重、健康史、精确位置和保密科研信息都不作要求。需要保密的信息请放在公开仓库之外。可复用资源见[示例目录](../examples/README.md)，提问和找搭子见[社区 Issue 说明（英文）](COMMUNITY.md)。
