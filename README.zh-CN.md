## 建群初衷

AI 科研发展很快，总有读不完的论文、跑不完的实验、需要检查的结果和接踵而至的 deadline。压力大的时候，运动和休息很容易成为最先被推迟的事情。

我发起这个俱乐部，是想找到一些同样认真对待科研和健康的同行。做 AI 研究的同时，我已经坚持健身十年，但仍在学习怎样让两者长期协调。最初的想法很简单：建一个聊天群，让大家分享经验、寻找运动搭子，互相鼓励着坚持下去。

短短几个小时，就有 200 多人加入。这个仓库希望把群里的交流沉淀下来：分享切实可行的计划，做简单的记录，从没能完成的训练中总结经验，也积累实用的科研与健身工作流。

我们想讨论的，都是具体的问题：

- AI 和科研安排不断变化，怎样给运动留出稳定的时间？
- 哪些训练安排更适合高强度脑力工作，又怎样影响我们各自的精力和恢复？
- 算上检查和返工，哪些任务交给 Agent 后真的能减轻负担？省下的时间，能否留给运动和生活？

我们希望慢慢找到一种中断之后也愿意回来的节奏。做好研究、保持健康、充分休息和认真生活，都值得拥有时间。

—— 发起人 Yukang Chen

## 面向哪些人

面向高校、科研机构和企业中实际从事 AI 研究的同行，也欢迎正在开展 AI 科研的学生。健身新手和有经验的运动者都欢迎加入。这里没有引用量门槛、身材要求，也不强制参加积分排名。

“薄肌”是俱乐部的名字，并不是对成员体型的要求。大家可以选择适合自己的运动、目标和公开参与程度。阅读、聊天、分享，或者安排一个恢复周，都是参与社区的方式。

## 三步开始参与

### 1. 周末提出下一周的计划

使用上方入口，为自己创建 **一个 weekly-plan Issue**。填写这一周周一的日期、自己的 IANA 时区，以及几次带有固定编号的计划训练：

```text
Week starting: 2026-10-26
Time zone: Asia/Shanghai
Participation mode: Active
Public leaderboard: No

S1 | Tuesday | 力量训练，约 30 分钟
S2 | Thursday | 篮球或快走
S3 | Saturday | 力量训练，约 30 分钟

Busy-week fallback: 至少安排一次简短训练；需要时调整其余计划。
```

请通过 Issue 表单填写；上面的示例用于说明各字段。表单字段名和 `Active`、`Recovery`、`Yes`、`No` 等选项保留英文，便于程序识别；训练内容和感受可以用中文书写。

`S1`、`S2`、`S3` 是你自己计划中各次训练的编号，不代表规定动作。`Active` 计划可以包含 1–14 次训练，使用 `S1` 至 `S99` 中互不重复的编号。星期请使用完整英文名称，即 `Monday` 至 `Sunday`。休息日写在 Notes 中，不计作训练次数。

按自己这一周的实际情况承诺。赶稿周安排少一些训练完全可以。如果想暂时退出计分，同时保留记录和复盘的空间，可以选择 **Recovery**。

### 2. 完成一次计划训练后，简单打卡

在自己的周计划 Issue 下评论：

```text
/done S1 2026-10-27 | 力量训练 30 分钟。今天有些累，所以降低了强度。
```

这样就够了。照片、具体动作、重量和时长都可以选填，附在命令后面的其他行。每条评论只放一个命令，每个计划编号最多计为完成一次。

日期填写该次训练在你所填时区中的实际日期，也允许之后补记。未来日期和不属于该计划周的日期不会计分。

不需要每天提 PR、上传证明照片，也不要求每天训练。缺少打卡只表示 **尚未记录**，不能据此判断一个人没有运动。计划之外的运动也可以直接评论分享，只是不额外增加执行积分。

### 3. 周末做一次简短复盘

新增一条以 `/review` 开头的评论，后面写几句反思：

```text
/review
做得好的地方：两次短训练，比一次长训练更容易安排。
遇到的障碍：周四的实验拖得比较晚。
下周调整：把那次训练提前，同时保留现实可行的最低方案。
```

无论这一周有没有按计划完成，复盘都能获得同样的积分。也可以选填运动后的精力、疲劳、睡眠感受，或记录一个帮你腾出时间的 Agent 工作流。科研产出和个人健康结果不参与评分。

## 每周积分：一点小小的鼓励

积分记录的是 **已记录的参与情况，以及个人计划的执行和复盘**，不代表健身水平、健康程度或训练能力。

| 项目 | 每周积分 | 规则 |
| --- | ---: | --- |
| 有效的 Active 周计划 | 1 | 每人每周使用一个有效的周计划 Issue |
| 已记录的计划执行情况 | 0–6 | `6 × 已完成的计划训练次数 / 计划训练次数`，四舍五入保留两位小数 |
| 周末复盘 | 2 | 计划作者发表一条非空的 `/review` 评论，与完成情况无关 |
| 有帮助的社区贡献 | 0–1 | 一条符合要求、并经维护者认可的经验分享 Issue |
| **每周上限** | **10** | 多练或多发帖都不会额外突破上限 |

**例子：** 计划训练 3 次，记录完成 2 次，并做了复盘：`1 + 6 × 2/3 + 2 = 7` 分。如果还有一条经认可的社区贡献，则为 `8` 分。

训练重量、里程、时长、消耗热量、减重幅度、外形、照片、点赞和引用量，都不会带来额外积分。不同的个人承诺可以获得相同分数。一个较轻松的计划也能拿满执行分，阅读榜单时需要考虑这一点。

积分按周重新计算。排行榜采用 **自愿加入** 的方式：在表单中选择 `Yes`，才会公开展示你的 GitHub 用户名。总分相同则并列排名。如果同一人重复提交周计划，使用最早创建的有效 Issue。

选择 Recovery，或由本人在自己的计划下评论 `/pause`，都会使该周退出积分排名。如果之后想恢复，编辑或删除那条暂停评论即可；`/pause` 不是重复输入就能切换状态的开关。

计划可以调整。请在评论里说明变化，保留已完成训练的编号，不要单纯为了提高分数而改写过去的承诺。第一版按照 **当前填写的计划** 计算，不会冻结最初的历史计划。这是一个基于诚信、没有现金奖励的社区。详细情况请查看[完整评分与特殊情况说明（英文）](docs/SCORING.md)。

## 经验、饮食与科研工作流分享

欢迎分享其他成员可以借鉴的具体经验：现实可行的训练安排、实惠的饮食思路、中断后恢复训练的经历，或者 Agent 辅助科研的工作流。请说明自己尝试了什么、有什么变化，以及这段经验的适用范围和局限。

分享 Agent 工作流时，可以使用这个结构：

> 自动化之前怎样完成任务 → Agent 分担了什么 → 仍需要哪些检查或返工 → 实际省下多少时间 → 是否因此为运动或生活留出了时间。

维护者为经验分享 Issue 加上 `points-approved` 标签后，它可以在所填写的那一周获得贡献积分。每人每周最多获得 1 分，多发帖或多个认可标签都不会突破上限。普通的同伴鼓励同样欢迎，不需要事事都对应积分。

饮食分享完全自愿。照片配上一点食材、分量和烹饪方式的说明，可以成为讨论的起点。第一版 **不提供自动饮食健康评分，也没有独立的饮食积分系统**。

Agent 可以描述照片中可见的食物、追问必要信息，并给出一条可选的改进建议，同时说明哪些内容无法判断。单餐照片无法代表一个人的整体饮食质量，图像估计也可能存在误差。相关背景可参考 [WHO 的健康饮食原则](https://www.who.int/news-room/fact-sheets/detail/healthy-diet)和[一项餐食照片评估研究](https://doi.org/10.3390/nu17040607)。

## 自动化负责什么

| 功能 | 第一版的做法 |
| --- | --- |
| 收集周计划和打卡记录 | GitHub Issue 表单和作者本人的评论 |
| 计算完成情况和积分 | 按确定规则运行的 Python 程序，无需 LLM 或付费 API |
| 公开每周榜单 | GitHub Actions 更新英文主 README 和 `reports/` |
| 认可有帮助的经验 | 由人工维护者添加 `points-approved` 标签 |
| AI 撰写周报、提供工作流建议 | 可选，由人工审核；流程见 [Agent 使用指南（英文）](docs/AGENT_GUIDE.md) |
| 自动医疗建议或饮食健康排名 | 不包含 |

仓库内的工作流计划在 **每天北京时间 09:15（Asia/Shanghai）** 运行，也可以手动触发。默认刷新当前周和上一周，方便补记近期记录；手动指定某一周时，会改为展示并刷新该周。下一次默认运行会恢复为当前周和上一周的视图。

选择报表周时采用 Asia/Shanghai 时区；每条训练日期则按参与者自己填写的时区解释。报表是可以更新的记录快照，并非不可修改的最终结算。GitHub 的定时运行可能有延迟。

文件进入仓库默认分支、并完成[设置步骤（英文）](docs/SETUP.md)之后，自动化才会开始生效。仓库目前没有配置外部 AI Agent 或相关凭证。

## 社区规则

1. **自愿参与。** 加入聊天群不代表必须公开打卡或加入排名。恢复、休息和重新开始都欢迎。
2. **支持现实可行的计划。** 尊重不同的起点、运动类型、工作安排和恢复需要，不鼓励带着伤痛或疾病勉强训练。
3. **诚实、简短地记录。** 记录自己的训练，填写实际日期，说明计划调整。无需照片认证，也不设置复杂的反作弊系统。
4. **互相帮助，尊重不同身材。** 不进行身材羞辱、未经邀请的体型评价或履历攀比，也不宣称某一种训练适合所有人。
5. **只分享有权公开的内容。** 未经许可，不发布他人的私人信息、可识别身份的照片或保密科研资料。不发广告，不刷屏。
6. **理解公开参与的范围。** Issue、评论、图片和已提交的历史记录可能公开可见并被保留。退出排名不会让 Issue 变成私密记录。照片、体重、体脂和健康史始终不作要求。
7. **明确 Agent 的使用边界。** 建议和总结用于参考，不能代替诊断。积分算术遵循公开规则，争议处理和贡献认可保留人工判断。

## 如何逐步改进

先由愿意参与的成员进行两周试运行。聊天群继续面向所有成员，包括不愿意在 GitHub 上打卡的人。我们会观察大家是否愿意继续参与、记录是否足够省事，以及是否真的为运动和恢复留出了时间。

自愿组成的小型运动搭子组，可以带来榜单之外的交流和鼓励。得到参与者同意之后，也可以把可复用的经验整理成训练资源和 Agent 工作流案例。新增功能应当确实减少负担，或者改善互相支持的体验。

欢迎提出功能建议、纠错和贡献代码。日常训练记录写在周计划 Issue 的评论中；可复用的文档和工具改进通过 PR 提交。
